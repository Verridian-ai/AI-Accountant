### NEON LOCAL — What it actually is

Neon Local is NOT a self-hosted Postgres. It is a Docker proxy container (`neondatabase/neon_local`) that:
- Creates ephemeral database branches when containers start
- Connects to Neon Cloud through a local Postgres endpoint
- Your app connects to `postgres://neon:npg@neon-local:5432/dbname?sslmode=require`
- Requires `NEON_API_KEY` and `NEON_PROJECT_ID` environment variables

Docker Compose config:
```yaml
neon-local:
  image: neondatabase/neon_local:latest
  ports:
    - '5433:5432'   # Different port to avoid conflict with Cognee's Postgres
  environment:
    NEON_API_KEY: ${NEON_API_KEY}
    NEON_PROJECT_ID: ${NEON_PROJECT_ID}
```

### NEON DATA MASKING — Beta Feature (CRITICAL for PII protection)

Neon has a **beta data masking feature** using the PostgreSQL Anonymizer extension (`anon`). This is CRITICAL for our use case because:
- Financial data contains PII (names, TFNs, bank account numbers, addresses)
- When Cognee/LLMs process data, we need masked versions
- Neon branches can be created with masked data automatically

How it works:
```sql
-- Enable the extension
SET neon.allow_unstable_extensions='true';
CREATE EXTENSION IF NOT EXISTS anon;

-- Define masking rules on columns
SECURITY LABEL FOR anon ON COLUMN transactions.description
IS 'MASKED WITH FUNCTION anon.fake_company()';

SECURITY LABEL FOR anon ON COLUMN employees.tfn
IS 'MASKED WITH VALUE ''***-***-***''';

SECURITY LABEL FOR anon ON COLUMN employees.bank_account_number
IS 'MASKED WITH FUNCTION anon.partial(bank_account_number, 2, ''****'', 2)';

SECURITY LABEL FOR anon ON COLUMN customers.email
IS 'MASKED WITH FUNCTION anon.fake_email()';
```

Available masking functions:
- `anon.fake_first_name()`, `anon.fake_last_name()`, `anon.fake_email()`, `anon.fake_company()`
- `anon.partial(col, keep_start, replacement, keep_end)` — partial scrambling
- `anon.random_int_between(min, max)` — randomize numbers
- `anon.noise(col, 0.1)` — add ±10% noise (good for amounts in dev)
- `anon.generalize_int4range(col, step)` — generalization
- `MASKED WITH VALUE 'CONFIDENTIAL'` — full redaction

### COGNEE + DATA REDACTION BEFORE LLM

Cognee does NOT have built-in PII redaction. We need to build a **custom Cognee pipeline task** that:
1. Reads financial data from Neon DB
2. Passes through a PII redaction layer BEFORE sending to cloud LLMs
3. The redaction can use:
   - **Option A**: Neon's masking branch — query from a masked Neon branch (data is pre-anonymized)
   - **Option B**: Application-layer redaction — regex/NLP scrubbing before Cognee pipeline
   - **Option C**: Hybrid — Neon masks at DB level + app-layer catches anything missed
