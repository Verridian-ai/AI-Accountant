## COST OPTIMIZATION STRATEGY — READ THIS FIRST

We are using a tiered model strategy to minimize cost while ensuring quality:

- **Haiku agents** (cheap, fast): Repetitive bulk work — Zod schemas, test files, grep/count audits, file cleanup
- **Sonnet agents** (mid-cost, capable): Heavy lifting — type system changes, Cognee integration, schema work, security middleware
- **ONE Opus 4.6 agent** (expensive, smartest): Quality gate ONLY — reviews completed work, catches bugs, approves checkpoints. Does NOT write code. Only reads and verifies.

The Opus agent must be EFFICIENT with tokens:
- It reads ONLY the diff/summary of what changed, NOT entire files
- It runs verification commands (tsc, grep, test) and checks output
- It sends short PASS/FAIL verdicts with specific line numbers if issues found
- It does NOT rewrite code — it tells the Sonnet/Haiku agent what to fix
